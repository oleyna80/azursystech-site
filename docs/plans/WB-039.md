## Owner activation procedure

Maintenance Mode is Owner-controlled and disabled by default: the state file
`.agent/maintenance-mode.json` is stored with `enabled: false`.

Activation is a deliberate Owner operation, run from the repository root:

```bash
python3 -c "import sys; sys.path.insert(0,'.agent/hooks'); from pathlib import Path; import maintenance_mode as m; m.activate(Path('.'), repository_identity=m.repo_identity(Path('.')), remediation_branch='<branch>', trusted_base='<40-hex base>', allowed_path_scope=[<explicit paths>], owner_authorization_ref='<Owner authorization ref>', activation_reason='<bounded reason>', downgraded_guard_classes=sorted(m.COOPERATIVE_CLASSES), activated_at='<ISO-8601 UTC>')"
```

`activate()` refuses the state unless the repository identity, remediation
branch, and `trusted_base` equal the live checkout, `hard_stop_classes` equal
the canonical immutable set, and `allowed_path_scope` is a non-empty explicit
list. Nothing in the state can add a hard-stop class or widen itself.

Deactivation and rollback restore normal enforcement immediately:

```bash
python3 -c "import sys; sys.path.insert(0,'.agent/hooks'); from pathlib import Path; import maintenance_mode as m; m.deactivate(Path('.'))"
```

Deactivation clears `enabled` and `activated_at`; the append-only
`.agent/maintenance-mode.audit.jsonl` is preserved as evidence. Every
downgraded decision appends one record carrying the branch, base, guard class,
operation, paths, reason, and `normal_lifecycle_approval: false`. Audit records
never grant authority and are never read as approval.
