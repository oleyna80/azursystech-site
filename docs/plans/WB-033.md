# WB-033 Implementation Plan

## Scope

This is a bounded inert refactor of `.agent/controllers/v1/**` under the
`Controlled` governance profile. The r2 source write-set is exactly:

```text
.agent/controllers/v1/**
.githooks/commit-msg
.githooks/tests/commit-msg-fixtures.sh
```

The controller will remain an unactivated package. The two named `.githooks/`
paths are the sole exception to the earlier no-hook rule: they reconcile the
approved short Work Block ID with local commit-message validation. No live
controller hook, SSOT schema, lifecycle script, manifest, or other governance
implementation will be changed.

## r2 admission and delivery sequence

1. Return to Define with `WB-033-r2.1`, the exact amended write-set, a blocked
   source gate, and Critic pending. Preserve prior r1 Critic reports.
2. Obtain a new independent read-only Critic verdict on this bounded amendment;
   reopen source writes only if it approves.
3. Change only the two admitted `.githooks/` files. Keep the Python active-ID
   and Bash trailer grammars semantically equivalent: `WB-` plus exactly three
   digits, or the existing dated lowercase-slug form. Require exact trailer
   equality with the active ID. Add fixtures for a matching short pair and
   matching dated pair; malformed short IDs (wrong digit count and suffix);
   valid-but-mismatched `WB-034` trailer; duplicate trailers; and preservation
   of branch mismatch, detached HEAD, malformed state, and inactive behavior.
   Do not bypass the hook.
4. Run the hook fixtures before and after the repair, then the full focused controller suite, diff checks, import
   smoke, and inert/live-control checks. Review exact staged paths.
5. Create a focused hook-repair commit, then the controller implementation
   commit, both with `Work-Block: WB-033`. If a hook rejects either commit,
   stop and preserve state.
6. Obtain fresh independent Reviewer and Verifier evidence only after both
   commits exist, bound to the combined final `HEAD`. Push only
   `HEAD:refs/heads/feat/governance-recovery-033`
   to `origin` after the live publication gate admits it; never merge or deploy.

## Implementation steps

1. Simplify the lifecycle state machine to `INACTIVE`, `DEFINE`, `EXECUTE`,
   and `ASSURE`, implementing the specified transition table, immutable
   closeout events, explicit Reviewer/Verifier rework, and fail-closed unknown
   transitions.
2. Simplify evidence and dispatch around one Git tree SHA `candidate_id`, the
   minimum role evidence record, immutable completed results, and one
   capability-freshness check before new dispatch. Do not add self or future
   hash dependencies.
3. Consolidate policy into one canonical evaluator covering write-set rules and
   External Hard Stops. Preserve bounded future subject-branch publication
   semantics while keeping push out of scope for WB-033.
4. Consolidate Codex and Claude runtime adapters so they normalize events and
   return canonical policy decisions without carrying separate policy logic.
5. Simplify atomic storage and bounded inactive recovery. Validate before
   persistence, use same-directory temporary replacement with the existing
   flush/sync support, re-read after uncertain replacement, and recover only
   provably canonical `INACTIVE` state.
6. Simplify the CLI and controller-side hook so lifecycle writes and policy
   evaluation use the shared state and policy functions.
7. Remove obsolete production modules and preserve only the minimum package
   structure required by the specification.
8. Rewrite the focused tests around state, evidence, policy, storage, adapters,
   and import or hook inertness.
9. Run the validation matrix below, including the before/after complexity
   inventory and live-surface checks. Confirm the worktree changes remain
   confined to the amended source write-set plus this coordination package.
10. Require independent Reviewer and Verifier evidence before any future
    activation decision. Activation itself is outside this Work Block.

## Required validation matrix

- Test every lifecycle transition in the specification, including success,
  reporting-only, cancelled, Reviewer rework, Verifier rework, material scope
  return to Define, unchanged-candidate assurance retry, and unknown-state or
  unknown-transition denial.
- Test the policy decision table: admitted local write, write-set escape,
  unknown state, each External Hard Stop, bounded subject-branch non-force push
  semantics, and ambiguous or unsafe push denial.
- Test one candidate identity mechanism: Git tree SHA binding, Reviewer and
  Verifier candidate match, separate session identities, immutable completed
  evidence, and no expiry of completed evidence.
- Inspect or test that no evidence artifact requires its own hash, a future
  commit SHA, or a self-referential ledger.
- Record the historical-to-target inventory for production modules, hook
  entrypoints, authority data families, lifecycle states, candidate identity,
  policy evaluators, freshness locations, and Codex/Claude policy copies.
- Test atomic persistence with temporary fixtures: validation before write,
  deterministic serialization, same-directory replacement, invalid-state
  rejection, and fail-closed handling of uncertain replacement.
- Test bounded recovery for provably inactive state and denial without
  authority reconstruction for active, corrupted, or ambiguous state.
- Run import, hook, mutation, and live-control-surface checks using fixtures
  only; verify `INERT_PACKAGE_PRESENT` and no activation or materialization.

## Risks and controls

- **Accidental authority weakening:** keep exact write-set, generation pinning,
  candidate binding, and fail-closed unknown-state behavior covered by focused
  tests.
- **Policy divergence:** use one canonical evaluator and make both adapters
  thin normalization and response layers.
- **Loss of valid fail-closed behavior:** test malformed state, ambiguous
  commands, unsafe push forms, invalid evidence, unknown transitions, and
  active or ambiguous recovery explicitly.
- **Accidental live controller-hook changes:** restrict source edits to the
  exact r2 write-set and verify the controller live control surface before and
  after tests; the local Git commit hook is intentionally changed.
- **Confusing mutation detection with true read-only isolation:** record actual
  pre/post mutation checks as evidence without claiming OS-level read-only
  enforcement.

## Verification boundary

Tests may inspect and use temporary fixtures inside their own test scope, but
must not modify live SSOT, live hooks, lifecycle scripts, manifest, or other
control-surface files. The package must remain `INERT_PACKAGE_PRESENT`; no
activation or materialization path may be invoked.
