# WB-036 — Hook Enforcement Audit & Alignment

## Objective and baseline

Audit the nine SDLC control points in `governance/enforcement.md` against the
current implementation on `audit/hook-enforcement-036` at
`703dcd05c0aa561d10571b4e1c652302769c1b06`. Align only demonstrated
gaps. The existing WB-035 lifecycle, separate Reviewer/Verifier evidence,
rework invalidation, frozen content identity, and exact subject publication
semantics remain authoritative.

## Requirements

- REQ-001: Persist a nine-point enforcement matrix with invariant, observed
  mechanism and coverage, preferred layer, overlap, gaps, and regressions.
- REQ-002: Add Git-native commit enforcement for staged scope and candidate
  linkage, including a bounded active-to-inactive terminal transition and
  ordinary canonical-inactive coordination commits. Git hooks call shared
  runtime-neutral policy instead of carrying lifecycle decisions.
- REQ-003: Add Git-native push enforcement using the existing shared
  publication predicate, with exact destination, sole update, and
  non-fast-forward denial. Runtime pre-tool control remains early defense.
- REQ-004: Preserve runtime pre-write and dangerous-operation guards and
  external Owner boundaries. Repair the demonstrated frozen-source commit
  contradiction in both runtime adapters by delegating that commit decision
  to the installed Git-native check; reject bypass flags and absent hooks.
- REQ-005: Preserve durable Critic, Reviewer, Verifier, test, and closeout
  evidence; return the operational state to canonical inactive only through
  the successful lifecycle closeout path if its exact prerequisites hold.
- REQ-006: Recheck Git-observable candidate and closeout invariants from the
  published Git objects in a CI/GitHub conformance job. Local Git/runtime
  hooks remain deterministic cooperative guardrails for supported normal
  execution, not a security boundary against arbitrary Bash execution.

## Acceptance criteria

- AC-001 [req=REQ-001]: The matrix addresses all nine points and distinguishes enforced,
  partial, cooperative, and external-only controls. It records exclusions and
  deferred work.
- AC-002 [req=REQ-002]: Scoped active commits, canonical-inactive coordination
  commits, and an exact bounded terminal closeout commit pass. Wrong branch,
  malformed state, out-of-scope/prohibited index paths, stale frozen source,
  malformed terminal child/diff, and missing or wrong Work-Block trailer fail.
- AC-003 [req=REQ-003]: Git pre-push validates the observed single origin
  subject-ref update, HEAD identity, fast-forward ancestry, and shared
  candidate/assurance policy. Wrong remote/ref, extra updates, default branch,
  non-fast-forward, changed candidate, and stale/missing assurance fail. The
  shared runtime guard checks the literal command and force options; external
  branch protection remains the consequential boundary because Git's pre-push
  event cannot reveal an unused force flag.
- AC-004 [req=REQ-004]: On the supported normal command path, a valid
  frozen-source direct `git commit` is allowed by the Codex and Claude
  adapters only when the native pre-commit hook is active. The shared
  poka-yoke rejects recognized `--no-verify`, `-n`, Git
  `-c core.hooksPath=...`, leading environment overrides, missing hooks,
  and stale source; positive and negative regressions pass. The adapters do
  not claim to prove that arbitrary Bash cannot assemble a wrapped bypass.
  The r15 bypass is a known capability-model limitation, and no agent is
  authorized to use it. Existing WB-035 lifecycle/publication and Git hook
  fixtures pass.
- AC-005 [req=REQ-005]: Separate read-only Reviewer and Verifier bind READY reports to the
  same final frozen source candidate. Commit and exact subject push the assured
  source candidate; then commit and exact subject push the bounded terminal
  canonical-inactive projection. Git and remote evidence confirms the final
  terminal SHA and branch. Reporting-only closeout is a blocked outcome, never
  a READY result. No merge or deploy occurs.
- AC-006 [req=REQ-006]: A CI/GitHub conformance job runs on every subject
  branch publication and PR update, including docs-only terminal updates.
  It checks out the exact event head SHA (the PR head, not a synthetic merge
  commit), validates the event branch, and fetches enough history to bind
  the Work Block range to a trusted default-branch ancestor. From published
  Git objects, it checks every Work Block range commit and the cumulative
  base-to-head changed paths. It fails closed on missing/malformed Work Block
  state, branch mismatch, wrong/missing `Work-Block:` trailers, forbidden or
  out-of-scope changed paths, wrong frozen source identity, stale/missing
  candidate-bound Critic, Reviewer or Verifier evidence, and a malformed
  terminal transition. A canonical-inactive coordination commit is a
  separate allowed case under AC-002.
  Positive active/terminal and negative cases are automated. CI cannot
  reconstruct the command that created a commit or an unused push force
  option. Repository-local bypass does not grant merge/deploy authority;
  required checks and Owner-controlled external boundaries remain necessary.

## Implementation approach and limits

Reuse `.agent/hooks/hard_stop_policy.py` for the WB-035 push predicate.
The new shared Git-transition policy consumes Git's staged/index and pre-push
event data and returns a fail-closed decision. Hook shells only resolve root
and invoke it. Keep pre-write runtime adapters because Git cannot observe an
attempted edit before staging. For frozen source commits, the adapters must
check that the native hook is installed and pass the command to that hook's
shared index policy; they must not apply the READY-only source-write predicate
to a commit. Reject `--no-verify` rather than permitting a hook bypass. Keep
other runtime screening as early defense. Keep the existing bypass detection
as poka-yoke for normal paths; do not add an external Git execution broker.
A future consolidation can remove
remaining duplication after equivalent runtime fixture coverage exists. Do not
rewrite controls for symmetry.

Closeout must preserve candidate-bound reports. Terminal projection is
separately checked against the exact assured active parent, bounded diff, and
canonical inactive child. Any unresolved prerequisite stops the successful
closeout and records a reporting-only blocked outcome; it cannot satisfy
AC-005 or the requested READY status.

For this WB, freeze requires a passing targeted Git-transition fixture suite,
published-tree CI conformance fixtures and workflow trigger check, existing
WB-035 lifecycle/publication fixtures, bootstrap hook check, and traceability
validation, recorded in `docs/reports/WB-036-tests.md`. A general
machine-readable freeze-check manifest is deferred. A broken new hook must be
repaired in the approved write-set and retested; bypass flags are forbidden.
