# WB-039 — SDLC Maintenance Mode / Repair Bootstrap

## Authority and scope

Owner authorization of 2026-09-27 and the refreshed audit contracts at
`63f959406f13456c52484ce0e5b0cd0040401f32` govern this Work Block. The audit head
was refreshed from `ae0b7b1485b0c2c68a70fd844b6cd140b8116777` to include the
runtime hook wiring paths. The repository is `azursystech`, remediation branch
`fix/sdlc-publication-bootstrap-039`, trusted base
`c4829e77e2e9ae6a694a7def87b381c54571fd6d`, and Architecture Freeze v0.6
remains authoritative. The earlier Publication Bootstrap artifacts were never
OPEN and are superseded.

This batch implements only the minimum explicit Maintenance Mode mechanism
needed to repair cooperative SDLC guards. It does not repair Git Transaction,
Contract Reader, Terminal Transaction, or the Assurance model, and it does not
open a normal source write gate. If a cooperative hook blocks the exact repair,
the work is recorded as Owner-authorized Maintenance Bootstrap; that status is
not normal lifecycle approval.

## Requirements

- REQ-001: Provide one shared, runtime-neutral, disabled-by-default maintenance
  state and decision evaluator consumed by both Codex and Claude cooperative
  guards.
- REQ-002: Bind an enabled state exactly to this repository, remediation branch,
  trusted base, and explicit control-plane path scope; reject wrong identity,
  branch, base, scope, malformed state, and out-of-scope paths fail closed.
- REQ-003: Keep immutable hard stops enforced in maintenance mode, including
  force/non-fast-forward push, merge, deploy/release, protected/default branch,
  tag/release, secrets/credentials, live production data/infrastructure,
  destructive cleanup without separate Owner approval, irreversible external
  effects, and arbitrary cross-repository writes.
- REQ-004: Downgrade only named cooperative guard classes to AUDIT/WARN in exact
  scope, log each downgraded decision durably, and never report normal lifecycle
  approval.
- REQ-005: Make activation and deactivation deterministic, reversible, and
  auditable; disabling the state restores current normal enforcement.
- REQ-006: Permit a verified same-repository worktree/session handoff and the
  minimum local repair operations needed to edit control-plane policy while
  preserving source authority boundaries.
- REQ-007: Treat runtime session termination as distinct from a lifecycle
  transition: an unresolved active Work Block must not force authoritative
  lifecycle mutation so a session can stop or restart, and reporting-only
  closeout keeps its normal lifecycle evidence and postconditions.
- REQ-008: Make cooperative shell-policy parsing quote-aware so quoted or
  search-text occurrences such as `2>/dev/null` are not treated as real write
  targets.
- REQ-009: Resolve runtime hook commands from a stable project root rather than
  the mutable session cwd, classify a missing or unresolvable hook entrypoint as
  a wiring failure distinct from a policy denial, and require every runtime that
  participates in remediation to consume the shared evaluator or to be
  explicitly declared unsupported for maintenance sessions.
- REQ-010: Provide regression coverage for nested-cwd hook resolution across the
  PreToolUse, PostToolUse, and Stop classes plus invalid-hook-path
  classification, and document the Owner activation/deactivation procedure,
  rollback, and stop boundary for the next remediation batch.

## Acceptance criteria

- AC-001 [req=REQ-001]: A shared module defines the versioned maintenance state,
  validation, decision result, and structured audit record. Codex and Claude
  route cooperative decisions through that module without separate maintenance
  semantics.
- AC-002 [req=REQ-002]: Disabled or missing state preserves current behavior.
  Enabled state is accepted only for the exact repository identity, branch,
  trusted base, and declared paths; wrong repository, branch, base, malformed
  state, path escape, and out-of-scope path return DENY without a write.
- AC-003 [req=REQ-003]: Hard-stop effects remain DENY in enabled mode, including
  force push, merge, deploy/release, default/protected mutation, tags/releases,
  credentials/secrets, live production data/infrastructure, destructive
  cleanup, irreversible external side effects, and cross-repository writes.
- AC-004 [req=REQ-004]: Each configured cooperative class (inactive
  coordination, local source gate, post-freeze staging, lifecycle sequencing,
  direct-single-Git, complex mutating Bash, verified same-repository handoff,
  and candidate/terminal sequencing) can return AUDIT/WARN only when its paths
  are in exact scope; every downgrade appends a structured record containing
  work block, class, operation, paths, branch, base, reason, and timestamp.
- AC-005 [req=REQ-005]: Explicit activation and deactivation are deterministic;
  repeated evaluation gives the same result, activation is rejected when
  required fields or immutable hard-stop declarations differ, and disabling
  immediately restores normal DENY behavior.
- AC-006 [req=REQ-006]: A verified handoff from another local session/worktree
  of the same repository and remediation branch is permitted only after the
  shared identity/base/scope checks; no source-candidate identity or source
  bytes are changed by the maintenance mechanism.
- AC-007 [req=REQ-003,REQ-004]: Focused tests cover positive and negative
  decisions, durable audit logging, both runtime adapters, and hard-stop
  preservation. Control-plane/conformance tests and the practical WB-038
  regression harness run where available; any new systemic blocker is recorded
  without widening this batch.
- AC-008 [req=REQ-001,REQ-005]: Documentation includes the exact activation
  procedure, allowed path scope, Owner authorization reference, rollback by
  disabling/removing the state, and evidence that no normal lifecycle approval
  is claimed.
- AC-009 [req=REQ-007]: With an unresolved active Work Block, a runtime session
  can terminate or restart without mutating authoritative lifecycle state;
  Stop-hook completion enforcement is AUDIT/WARN in maintenance scope, and
  `closeout_mode=reporting-only` is not a generic session-exit escape hatch.
- AC-010 [req=REQ-008]: Cooperative shell-policy parsing treats quoted and
  search-text tokens, including `2>/dev/null`, as inert text rather than write
  targets, producing no false write-path classification.
- AC-011 [req=REQ-009]: Claude hook commands resolve from a stable project root;
  after a session changes cwd, including into a nested repository directory, the
  configured PreToolUse, PostToolUse, and Stop entrypoints still resolve and
  execute.
- AC-012 [req=REQ-009]: A missing or unresolvable hook entrypoint is reported as

- AC-013 [req=REQ-009]: Every runtime participating in remediation either

- AC-014 [req=REQ-009]: `.codex/hooks/pre_tool_use_policy.py` is writable from the

- AC-015 [req=REQ-010]: Regression coverage exists for nested cwd × PreToolUse,

- AC-016 [req=REQ-010]: The Owner activation/deactivation procedure, rollback,
  and stop boundary for the next remediation batch are documented.

## State contract

The state is JSON schema version `1`, with `enabled`, `repository_identity`,
`remediation_branch`, `trusted_base`, `allowed_path_scope`,
`owner_authorization_ref`, `activation_reason`, `activated_at`,
`downgraded_guard_classes`, and immutable `hard_stop_classes`. Missing or
malformed state is disabled for reads but fails closed for any requested
maintenance downgrade. `hard_stop_classes` must equal the canonical set in the
shared evaluator. Normal lifecycle state remains authoritative for normal
approval and is never rewritten by this mechanism.

## Bootstrap and rollback

Before implementation, record the blocked normal transition and Critic capacity
status. Under the explicit Owner authorization, local reversible edits may
continue as Maintenance Bootstrap while all hard stops remain active. Activation
is a deliberate Owner operation within this branch and scope. Rollback is to
disable the state and preserve the audit log; normal guards then enforce their
existing decisions. No force push, merge, deploy, release, or production
mutation is permitted.
