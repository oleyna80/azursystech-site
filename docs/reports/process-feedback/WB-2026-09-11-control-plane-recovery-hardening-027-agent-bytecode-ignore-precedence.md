# Process Feedback — `.agent` bytecode ignore precedence

## Observation

The repository ignored `__pycache__/` and `*.pyc` before re-including the
committed `.agent/**` policy tree. The later `!.agent/**` rule therefore made
generated Python bytecode visible, including
`.agent/hooks/__pycache__/hard_stop_policy.cpython-314.pyc`, which blocked the
clean terminal publication predicate.

## Evidence and cause

- Work Block: `WB-2026-09-11-control-plane-recovery-hardening-027`.
- `git check-ignore -v` matched the generated path against
  `.gitignore:99:!.agent/**`, proving the later re-include overrode the broad
  Python cache rules.
- `.agent/hooks/hard_stop_policy.py` and normal `.agent` policy files remained
  intended committed sources, so a broad `.agent` ignore would be incorrect.
- Confirmed root cause: repository-local `.gitignore` precedence mismatch
  between the committed `.agent` re-include and generated Python cache rules.

## Impact and follow-up

Generated bytecode appeared as an untracked artifact after hook execution and
prevented clean terminal publication. The narrow rules
`.agent/**/__pycache__/` and `.agent/**/*.pyc` must follow the `.agent/**`
re-include section. Validate generated-cache ignore and source trackability
with `git check-ignore`; do not broaden the ignore or suppress hard stops.
