## 1. Цель документа

Зафиксировать стратегию работы с Facebook-группами для **AzurSysTech**, чтобы:

- находить релевантные группы, а не публиковаться хаотично
- понимать, в какие группы стоит идти в первую очередь
- не тратить время на группы без лидового потенциала
- не выглядеть спамером
- связывать активность в группах с лидами и трафиком на сайт

---

## 2. Основной принцип

### Group outreach philosophy
Facebook-группы на старте — это не массовый “спам-канал”, а:

- локальный источник первых заявок
- канал доверия
- место, где можно встретить уже “тёплую” потребность
- способ получить первые диалоги быстрее, чем через SEO

### Core rule
Работа с группами должна быть:
- выборочной
- локальной
- осторожной
- человеческой
- ориентированной на пользу и релевантность

---

## 3. Задачи группового канала

### Main goals
1. получить первые входящие сообщения
2. получить первые переходы на сайт
3. найти реальные бытовые и бизнес-запросы
4. встроиться в локальное сообщество
5. понять, какие темы лучше всего цепляют рынок

### Secondary goals
- собрать первые кейсы
- протестировать формулировки офферов
- понять язык аудитории
- найти группы, куда потом можно заходить регулярно

## 6. Group qualification criteria

Перед тем как тратить время на группу, её нужно быстро оценить.

### Main criteria
- локальность
- релевантность тем
- живая активность
- нормальная модерация
- допускаются ли рекомендации / услуги
- нет ли жесткого запрета на self-promo
- есть ли реальные запросы от людей

### Good signs
- люди спрашивают “кого посоветуете?”
- есть локальные сервисные запросы
- есть бытовые / бизнес-проблемы, связанные с техникой
- посты получают ответы
- группа не выглядит мёртвой

### Red flags
- группа мёртвая
- только спам
- администрация резко удаляет сервисные посты
- нет локальной релевантности
- аудитория слишком размыта

## 7. Suggested group scoring model

### Scoring factors
Можно оценивать группы по простой шкале 1–5 по таким параметрам:

- local relevance
- activity
- service friendliness
- audience fit
- business fit
- home-user fit

### Example interpretation
#### High priority group
- local
- active
- requests happen
- moderation tolerates useful service posts

#### Medium priority group
- active, but less targeted
- can still be useful for occasional posts/comments

#### Low priority group
- weak fit
- no clear demand
- too much spam
- dead or over-restricted

## 10. Recommended initial target list size

### MVP recommendation
Не начинать сразу с 30–50 групп.

### Better approach
Start with:
- **8–15 групп**
- потом сократить до:
  - strongest 5–8
  - and keep a second-tier list

### Why
Так проще:
- тестировать
- отслеживать отклик
- не распыляться
- не превращать процесс в хаос

## 11. Group outreach modes

### Mode A — Direct value post
Ты публикуешь собственный пост по правилам группы.

### Mode B — Soft intro post
Более мягкий пост без “жёсткой рекламы”.

### Mode C — Response to existing request
Самый сильный режим:
- кто-то уже ищет специалиста
- ты отвечаешь в комментарии / DM

### Mode D — Relationship presence
Периодически участвуешь в группе как спокойный, полезный локальный специалист.

### Recommendation
На старте strongest mode:
- **Mode C**
- plus selected Mode A / B

## 12. Posting rules by group type

# Local city groups
### Best approach
- мягкие локальные посты
- practical service framing
- не слишком много технического текста

# Expat / Russian-speaking groups
### Best approach
- просто и по-человечески
- сильный trust angle
- easy-to-contact framing

# Small business groups
### Best approach
- business-first posts
- рабочие места / Wi-Fi / printers / no in-house IT
- structured and calm tone

# Services / recommendation groups
### Best approach
- very short service post
- direct usefulness
- clear geography
- fast CTA

# Neighborhood groups
### Best approach
- local proximity
- бытовые задачи
- short and polite presence

## 13. What to post in groups

### Best themes for launch
- настройка нового ПК
- Wi-Fi и принтеры
- выездная IT-помощь
- рабочие места для TPE
- помощь маленькому офису / кабинету
- бытовые и home-office задачи
- “можно просто написать и описать проблему”

### What NOT to post first
- сложные системные темы
- AI / automation / infrastructure geek content
- длинные статьи
- очень “брендовые” рекламные блоки
- heavy corporate language

---

## 14. Outreach rhythm

### Recommended launch rhythm
- 2–4 meaningful group activities per week

This includes:
- 1–2 own posts
- 1–3 replies to existing requests
- 1–2 useful comments if relevant

### Rule
Quality > quantity

### Important note
Лучше 2–3 хорошие точки входа в неделю, чем 10 одинаковых спам-постов.

---

## 15. Comment-first strategy

### Strong recommendation
На старте часть лучших лидов может приходить не из собственных постов, а из:
- ответов на чужие запросы
- рекомендационных тредов
- комментариев под проблемными постами

### Why
Это уже активный спрос, а не попытка его “создать с нуля”.

### Therefore
В tracking нужно фиксировать отдельно:
- own group posts
- replies to request posts
- DMs from groups

## 17. Outreach operating procedure

### Step 1
Собрать shortlist групп.

### Step 2
Оценить правила, активность, тип аудитории.

### Step 3
Определить priority:
- high
- medium
- low

### Step 4
В high-priority groups:
- наблюдать
- ответить на существующие релевантные запросы
- потом публиковать аккуратный свой пост

### Step 5
Фиксировать в tracking sheet:
- дату поста / комментария
- отклик
- переходы
- лиды

- `facebook_group`
- `facebook_messenger`

### Mapping
| inbound scenario | source tag |
|---|---|
| Website form submit | `website_form` |
| Website chat handoff submit | `website_chat` |
| Facebook Page post -> lead | `facebook_page` |
| Facebook Group post/comment -> lead | `facebook_group` |
| Messenger DM lead | `facebook_messenger` |
| Direct typed URL / unknown direct contact | `direct` |
| Recommendation/referral | `referral` |
| Google Business Profile lead | `google_business_profile` |
| Organic Google traffic | `organic_search` |
| Cannot determine source | `unknown_source` |

### Rule
Do not use `facebook_group_local` / `facebook_group_business` as source tags.
Use them only as campaign/group classification.

## 23. UTM convention

### Facebook Page post
`utm_source=facebook&utm_medium=social&utm_campaign=page_post_[topic]`

### Facebook Group post
`utm_source=facebook&utm_medium=group&utm_campaign=group_post_[topic]`

### Facebook Group comment reply
`utm_source=facebook&utm_medium=group_comment&utm_campaign=group_reply_[topic]`

### Messenger follow-up link
`utm_source=facebook&utm_medium=messenger&utm_campaign=dm_followup_[topic]`

### Naming rule
`[topic]` should be short and stable, for example:
- `wifi`
- `printer_setup`
- `new_pc`
- `small_office`

## 24. Group-level KPIs

### Track manually at first
- number of groups joined
- number of groups qualified as useful
- number of posts made
- number of comments/replies made
- number of DMs received
- number of website visits from group links
- number of leads from groups
- number of qualified leads from groups

### Main KPI
Не “охваты”, а:
- сообщения
- заявки
- qualified leads

---

## 25. Red-list rules

### Avoid overcommitting to groups where:
- every post is deleted
- no local relevance
- no requests happen
- members never engage
- only spam exists
- moderation is unpredictable and hostile

### Rule
Do not keep posting in low-yield groups just because they are large.

## 26. Acceptance criteria

Groups outreach framework is valid if:
- ясно, какие группы искать
- есть логика приоритетов
- есть критерии отбора
- есть tracking structure
- есть balance между home-user и business lead capture
- outreach можно вести системно, а не хаотично
- source tags выровнены с `lead-taxonomy.md`
- UTM protocol зафиксирован и используется
